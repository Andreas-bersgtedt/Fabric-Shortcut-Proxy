File and Object Storage Sources

Serve existing files from a storage backend through this proxy's S3 endpoint, alongside your database tables. Backends: local — a filesystem path (an OS-mounted NFS or SMB share, e.g. \\server\share or /mnt/share); s3 — a native upstream S3 / MinIO / S3-compatible bucket; and azure — a native Azure Blob / ADLS Gen2 container. Each mount maps one S3 bucket to a backend and is served read-only. Changes save to config.mounts.json and apply on the next restart.
Enable storage proxy (ENABLE_STORAGE_PROXY)

Open Mirroring Targets

Push source tables into a Microsoft Fabric Open Mirroring landing zone. Each target reuses an existing source connection (configured on the Connection tab) and writes Parquet data files plus _metadata.json to the mirrored database's landing zone. Saved to config.open_mirror.json; applies on the next restart. See the landing-zone format.
Publish reads the saved targets (save first). OneLake targets need the onelake extra installed and the proxy's Entra identity configured.
