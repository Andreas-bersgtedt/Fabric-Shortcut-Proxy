Request branches

The bucket and object key determine which branch owns the read.

Metadata

  1. Resolve table snapshot
  2. Read or build metadata bytes
  3. Declare exact split paths and sizes
  4. Return Iceberg or Delta object

Parquet split

  1. Check pinned cache or artifact store
  2. Build parameterized split SQL on miss
  3. Encode rows as Parquet
  4. Serve complete or ranged bytes

Mounted bucket

  1. Resolve mount and confine prefix
  2. Select local, S3, or Azure backend
  3. Stream requested byte range
  4. Write access or denial audit event

Lite end-to-end lifecycle

The operator or external service manager owns the single Agent process. Accent-topped steps are ownership handovers.

01 · HANDOVEROperator to processInstall core package; provide JSON and environment
02Agent startupValidate config, reflect schemas, choose split keys
03Prepare tablesBuild snapshots; eager, lazy, virtual, or refresh path
04 · HANDOVERRuntime to FabricReadiness succeeds; shortcut targets port 9000
05Serve and observeS3 reads, metrics, monitor, logs, refresh
06 · HANDOVERExit to operatorExternal owner handles restart or config correction

Lite startup decisions

Auto refresh

  1. Materialize content-addressed table
  2. Publish current snapshot
  3. Prime source change probe
  4. Start freshness poller

Eager

  1. Build split descriptors and ranges
  2. Generate every split
  3. Pin authoritative bytes
  4. Publish Delta log when selected

Lazy or virtual

  1. Build descriptors without full reads
  2. Wait for metadata or data access
  3. Generate before declaring exact size
  4. Pin in lazy; evict in virtual

Enterprise control handover

The operator starts one Manager. The Manager becomes the process owner and passes a fleet contract to each Agent.

01 · HANDOVEROperator to ManagerLauncher prepares packages, ports, count, gateway, and HA
02Manager startupHydrate credentials, validate config, acquire HA lease
03 · HANDOVERManager to supervisorCreate one child owner per Agent index
04Spawn contractID, port, shard, mode, Manager URL, shared store
05 · HANDOVERAgent to registryRegister, receive lease, report epochs by heartbeat
06Fleet readyGateway or external LB sends S3 reads to live Agents

Fleet ownership lanes

Operator

  • Starts and stops Manager
  • Sets desired fleet count
  • Corrects permanent config faults
  • Keeps control port private

Manager

  • Owns control and admin APIs
  • Maintains registry and HA role
  • Creates supervisors
  • Optionally proxies S3 traffic

Supervisor

  • Spawns one child process
  • Samples process memory
  • Restarts with backoff
  • Stops on exit 78 or crash loop

Agent

  • Owns S3 auth and serving
  • Builds assigned splits
  • Publishes to shared store
  • Registers and heartbeats

Failure and HA decisions

Transient Agent crash

  1. Supervisor sees child exit
  2. Record restart in rapid window
  3. Wait configured backoff
  4. Spawn and register replacement

Permanent Agent fault

  1. Agent exits with code 78
  2. Supervisor does not restart
  3. Manager control UI stays available
  4. Operator fixes config, then restarts

Manager leadership loss

  1. Lease renew fails
  2. Former primary stops Agents
  3. Standby acquires shared lease
  4. New primary starts supervised fleet
